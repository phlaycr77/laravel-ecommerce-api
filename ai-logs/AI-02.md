## [AI-02] Xây dựng Middleware phân quyền Admin & Chặn tài khoản bị khóa (`TM-04`)

- **Ngày thực hiện:** 13/11/2026
- **Chức năng / Thẻ Trello:** `[TM-04]` Phân quyền RBAC & Chặn truy cập trái phép `/api/admin/*`
- **Công cụ AI sử dụng:** Gemini
- **Prompt đã dùng:** 
  > "Viết Middleware trong Laravel 10 sử dụng guard `auth:api` (JWT) để bảo vệ nhóm route `/api/admin/*`: kiểm tra người dùng đã đăng nhập chưa, tài khoản có đang hoạt động (`is_active = true`) không và có đúng vai trò `admin` không, trả về mã lỗi JSON chuẩn RESTful."

- **Kết quả AI đề xuất & Đánh giá chọn lọc:**
  - **Phần giữ lại:** Logic kiểm tra tuần tự 3 điều kiện (chưa xác thực trả về HTTP `401`, tài khoản bị khóa `is_active == false` trả về HTTP `403`, sai vai trò `role !== 'admin'` trả về HTTP `403`) và trả về cấu trúc JSON thống nhất[cite: 27].
  - **Phần loại bỏ / Tự chỉnh sửa:** AI ban đầu dùng `redirect('/login')` mặc định của web session khi chưa đăng nhập; đã sửa lại thành `response()->json(['message' => 'Unauthorized'], 401)` để phù hợp chuẩn Backend RESTful API và kiểm thử qua Postman[cite: 27].

- **Cách kiểm chứng thực tế:**
  1. Gọi `GET /api/admin/products` không gửi kèm Bearer Token $\rightarrow$ Hệ thống trả về `401 Unauthorized`.
  2. Đăng nhập bằng tài khoản khách hàng (`khachhang1@gmail.com`) lấy JWT và gọi vào `/api/admin/products` $\rightarrow$ Bị chặn với mã `403 Forbidden`[cite: 15].
  3. Đăng nhập bằng tài khoản bị khóa (`khachhang10@gmail.com`, `is_active = false`) $\rightarrow$ Bị chặn ngay với mã `403 Forbidden`.
  4. Đăng nhập bằng tài khoản quản trị (`admin@bookstore.vn`) $\rightarrow$ Truy cập thành công (`200 OK`).
